先给你吃颗定心丸：**五人工科小组的组长，核心不是“你技术最强、什么都自己干”，而是“把目标说清、把任务拆开、把进度盯住、把接口对齐、把风险兜住”。** 你不需要一上来就会领导，按下面这套流程做，基本不会乱。

---

## 一、上任第一周：先做这5件事

### 1. 找老师/助教确认“验收标准”
不要只问“任务是什么”，要问清：
- 最终交付物是什么？报告、代码、实物、PPT、演示？
- 截止时间是什么？有没有中期检查？
- 评分标准是什么？创新性、完成度、文档、答辩各占多少？
- 有没有格式、提交方式、禁止事项？
- 哪些问题可以问，哪些要自己决策？

**组长必须把“什么算完成”搞清楚**，否则全组会白干。

### 2. 开一次30分钟启动会
议程建议：
1. 我复述任务目标和验收标准，大家补充；
2. 每人说自己的技术强项、兴趣、可投入时间；
3. 初步拆分任务模块；
4. 定沟通规则：群、文档、会议时间；
5. 定下一次检查时间。

会上你要说清：**“我先负责协调和兜底，技术方案大家一起定，但每个模块要有唯一负责人。”**

### 3. 做任务分解，不要按“人”分，先按“交付物”分
工科项目常见拆法：
- 需求/方案设计
- 硬件/代码/实验模块A、B、C
- 接口定义与联调
- 测试与验证
- 文档与报告
- PPT/答辩/演示

然后落到表里：

| 任务 | 负责人 | 协作者 | 交付物 | 截止时间 | 依赖谁 | 状态 |
|---|---|---|---|---|---|---|
| 方案设计 | 张三 | 全员 | 一页方案图 | 周几 | 无 | 进行中 |
| 模块A | 李四 | 王五 | 可运行代码 | 周几 | 接口定义 | 未开始 |

**每项任务只能有一个负责人**，否则等于没人负责。

### 4. 明确角色，但不要官僚化
五人小组可以这样：
- 组长：进度、协调、对外沟通、风险兜底；
- 技术负责人/架构接口：可由技术强的同学担任，但方案要评审；
- 文档与版本管理员：维护共享文档、命名规范、提交记录；
- 测试/集成负责人：盯联调和验收；
- 汇报/材料负责人：PPT、报告统稿。

角色可以兼任或轮换，但**接口、文档、测试必须有人盯**。

### 5. 建三个共享物
- 一个共享文件夹/云文档：放需求、会议记录、报告；
- 一个任务看板：飞书/腾讯文档/Trello/Excel都行；
- 一个群公告：写清目标、截止、会议、文件命名规则。

文件命名建议：`模块_版本_日期_负责人`，例如 `电机控制_v2_0512_李四`。

## 二、执行期：用“短会+看板+接口”管住五个人

### 1. 每周一次15分钟站会
每人只回答三个问题：
1. 上次到现在完成了什么？
2. 下一步做什么？
3. 卡在哪里，需要谁支持？

**不要开成技术辩论会**，复杂问题会后拉相关人。

### 2. 每两天看一次任务看板
状态只用：未开始 / 进行中 / 待联调 / 完成 / 阻塞。
发现“进行中”超过3天没变化，就私下问一句：是任务太大，还是卡住了？

### 3. 工科项目最关键：先定接口，再并行开发
你们最容易翻车的地方不是个人不努力，而是最后集成对不上。所以要提前写清：
- 模块输入输出是什么？
- 数据格式、接口参数、电压/尺寸/协议？
- 谁提供、谁调用、什么时候联调？
- 版本怎么兼容？

**先做最小可运行版本，再逐步加功能。** 不要五个人各做各的，最后一周才合并。

### 4. 设置三个检查点
- **方案冻结点**：需求、模块划分、接口确定，之后改要说明影响；
- **联调点**：至少提前总截止的1/3开始联调；
- **版本冻结点**：截止前2—3天停止加新功能，只修bug、补文档、练答辩。

### 5. 决策机制提前说清
技术方案有分歧时：
1. 先让提出方案的人讲清成本和风险；
2. 相关模块负责人必须表态；
3. 组长拍板并记录理由；
4. 如果涉及老师要求，带方案去问老师，不要空手问。

## 三、怎么对人：不靠吼，靠规则和记录

### 1. 分工时“自愿+指定”结合
先问大家想做什么，再根据任务需要指定。说清楚：
> “这个模块你负责，不是说你一个人全干，遇到问题可以在群里拉人；但交付时间和联调你要盯到底。”

### 2. 对划水/拖延：三步走
1. **私下问原因**：是任务不清、能力不够、时间冲突，还是态度问题；
2. **重新明确**：任务、截止、交付标准、需要谁配合，发到群里留痕；
3. **升级处理**：仍不推进，组长在组会上说明影响，必要时找老师/助教，不要一个人忍到最后。

### 3. 让贡献可见
周报里记录每人完成项；答辩/报告里写清分工；对帮忙联调、补文档的人公开感谢。小团队最怕“干多干少一个样”。

### 4. 组长不要包揽
你可以兜底，但不要替所有人写代码/写报告。正确说法：
> “这部分我可以帮你一起定位，但主责还是你，今晚我们先看接口。”

## 四、对外沟通：对老师要“带方案汇报”

定期给老师/助教发简短周报：
- 本周完成；
- 下周计划；
- 当前风险/需要老师确认的问题；
- 问题尽量附2个可选方案。

不要只发“老师我们做不出来”，要发：
> “A方案成本低但精度不够，B方案精度高但时间多2天，我们倾向B，您看是否可行？”

这样老师会觉得你靠谱。

## 五、五人工科小组常见坑

1. **一开始不拆任务，大家“一起做”** → 实际没人负责；
2. **需求没确认就开工** → 做完发现方向错；
3. **不定义接口，最后集成崩** → 提前联调；
4. **组长一个人干最多** → 短期快，长期团队失效；
5. **怕得罪人不记录** → 出问题说不清；
6. **文档最后补** → 报告、答辩、复现都痛苦；
7. **截止前还加功能** → 必须版本冻结；
8. **开会没结论** → 每次会议记录“谁、做什么、何时完成”。

## 六、你可以直接套用的周会模板

**会议议程（20分钟）**
1. 目标回顾：本周要交付什么（2分钟）
2. 每人三件事：完成/下一步/阻塞（每人2分钟）
3. 接口与联调确认（5分钟）
4. 风险与决策（3分钟）
5. 明确下周任务表（3分钟）

**会议记录格式**
- 日期：
- 结论：
- 任务：负责人 / 截止 / 交付物
- 风险：
- 需要老师确认：

## 七、你明天就可以做的行动清单

1. 找老师确认验收标准和截止时间；
2. 建共享文档、任务表、群公告；
3. 约全组开30分钟启动会；
4. 让每人写“强项+可投入时间+想做模块”；
5. 你出一版任务分解草稿，会上一起改；
6. 定下第一次联调日期，而不是只定最终截止；
7. 每周发一次三行周报给老师/助教。

**记住一句话：组长的主要产品不是代码，而是“清晰的约定和持续的推进”。** 你不需要一窍不通就全会，你只需要把“目标—分工—接口—检查—兜底”这五件事跑起来。先开好第一次会、做好第一张任务表，你就已经超过很多小组长了。
