## 0. 一页纸结论

| 项目 | 结论 |
|---|---|
| 文件 | `src/preprocess.py` |
| 唯一对外函数 | `preprocess(audio_path, frame_ms=25.0, hop_ms=10.0) -> dict` |
| 流程 | 读 wav → 转 float64 → 多声道平均 → **除以全局最大绝对值** → 按 25/10 ms 分帧 → 返回 5 键字典 |

| 不做 | 不重采样、不降噪、不去直流、不加窗、不写中间 wav、不做端点检测、不支持 mp3 |

### 0.1 本轮已确认的六个决策

| 议题 | 决定 | 理由 |
|---|---|---|
| 交付形式 | 本轮只交付计划文档，代码下一步实现 | 先冻结接口，避免 M2/M3/M4 返工 |
| 分帧尾部 | **丢弃**不足一帧的尾部，与 MATLAB `enframe` 一致；整段短于一帧时补零成 1 帧 | 帧数公式可预测；末端不足 `hop_len`，对切音影响 < 10 ms |
| 加窗 | `frames` **不加窗**，保持原始采样 | 短时能量/过零率必须基于真实帧能量；Hamming 留给频域模块 |
| 双声道 | 两声道（含多声道）**取平均**下混 | 能量更完整；下混在归一化之前完成 |
| 返回键 | **严格 5 个**：`y_raw`、`frames`、`sr`、`frame_len`、`hop_len` | 接口冻结；帧数用 `frames.shape[0]` 获取 |
| 输入格式 | **只支持 wav**（`scipy.io.wavfile`） | 零额外依赖；mp3 由 GUI 层先转 wav |

## 1. 目标、边界与系统位置

### 1.1 目标

把任意一段 wav 一次性转换成下游三个模块可直接消费、量级统一的分帧数据，并**把帧长、帧移、采样率一起返回**，使 M2/M3/M4 不必重复读盘、重复分帧、重复换算。

### 1.2 做什么（In scope）

1. 读取 wav 文件，拿到采样率和原始采样；
2. 多声道下混成单声道；
3. 对整段信号做幅度归一化（除以最大绝对值）；
4. 把 `frame_ms`、`hop_ms` 换算成采样点数；
5. 做重叠分帧，得到二维帧矩阵；
6. 返回包含全部上下文信息的字典。

### 1.3 不做什么（Out of scope，防止范围蔓延）

| 不做 | 原因 / 归属 |
|---|---|
| 重采样到 44.1 kHz | 计划 §4.2 明确“Goertzel 按实际 fs 算，不强制重采样”；`sr` 原样返回 |
| 降噪、去直流、预加重、自动增益、限幅 | 论文第 2 节只要求“幅度归一化”，多加一步都会改变 M4 相关判决的前提 |
| 加 Hamming 窗 | 见 §3.2 / §10；窗属于频域分析，不属于分帧 |
| 逐帧归一化 | 会破坏帧间能量可比性，端点检测无法用统一阈值 |
| 写“前期处理好的音频文件”到磁盘 | 分工表“输出”一列写的是文件，但详情规定的返回值是 dict；**以 dict 为准**，主流程内存传递，避免二次量化 |
| 端点检测 / 切音 | 模块 M2（`segment_notes.py`） |
| 读 mp3 / 录音设备 | GUI 层负责转 wav；本模块只认 wav 路径 |

### 1.4 数据流与下游消费方式

```
wav 文件
   │
   ▼
preprocess()  ──►  { y_raw, frames, sr, frame_len, hop_len }
                        │        │
                        │        └──► M2：在 frames 上算 STE / ZCR，得到起止“帧索引”
                        └───────────► M2：用 y_raw 按帧索引切出单音（不经 frames 重组，避免边界误差）
                                             │
                                             ▼
                                     M3 Goertzel → L2 归一化 → M4 匹配滤波 → 判决
```

**设计要点**：`frames` 只用于“判断音在哪里”（能量/过零率），`y_raw` 才是“切音的数据源”。两者通过 §3.4 的索引映射严格对齐，这样切出来的音符不会因为帧重叠而重复或丢样点。

## 3. 接口契约（冻结）

### 3.1 函数签名

```python
def preprocess(audio_path: str, frame_ms: float = 25.0, hop_ms: float = 10.0) -> dict:
```

| 参数 | 类型 | 默认 | 约束 | 说明 |
|---|---|---|---|---|
| `audio_path` | `str` | 必填 | 文件存在、可读、PCM/float wav | wav 文件路径；也接受 `pathlib.Path`（按 `str` 处理） |
| `frame_ms` | `float` | `25.0` | `> 0` 且 `>= hop_ms` | 帧长（毫秒） |
| `hop_ms` | `float` | `10.0` | `> 0` 且 `<= frame_ms` | 帧移（毫秒） |

**约束理由**：`hop_ms > frame_ms` 会在相邻帧之间留下空隙，短时能量曲线出现断点，M2 的端点检测可能漏掉音头或音尾，因此直接 `ValueError`，不做“允许但警告”。

### 3.2 返回字典（**恰好 5 个键**）

| 键 | 类型 | 形状 | 取值范围 | 用途 | 消费者 |
|---|---|---|---|---|---|
| `y_raw` | `np.ndarray` (`float64`) | `(L,)` 一维 | 非静音时 `[-1, 1]` 且峰值 `= ±1` | 归一化后的整段信号；**切音的唯一数据源** | M2、GUI 波形 |
| `frames` | `np.ndarray` (`float64`) | `(n_frames, frame_len)` 二维 | 与 `y_raw` 同量级 | 短时能量、过零率、分帧可视化 | M2、GUI |
| `sr` | `int`（Python 原生） | 标量 | 原文件采样率，如 44100 | Goertzel 频率轴、时间换算 | M2/M3/M4/GUI |
| `frame_len` | `int`（Python 原生） | 标量 | 25 ms 对应点数，如 1103 | 帧 ↔ 采样点换算 | M2/M3 |
| `hop_len` | `int`（Python 原生） | 标量 | 10 ms 对应点数，如 441 | 帧 ↔ 采样点换算 | M2/M3 |

**明确不返回**：`n_frames`（用 `frames.shape[0]`）、`duration`、归一化前的原始信号、`peak`、窗函数、任何调试字段。

**明确类型细节**：
- `y_raw`、`frames` 一律 `float64`（Goertzel 递推对精度敏感，不用 `float32`）；
- `frames` 必须是 **C 连续、可写**的数组（`np.ascontiguousarray` 拷贝），不能是只读视图；
- `sr`、`frame_len`、`hop_len` 用 `int()` 转成 Python 原生整数，避免 GUI/JSON 序列化时出现 `np.int64`。

**返回值示例**（44.1 kHz、1 s、25 ms/10 ms 的 wav）：

```python
{
    "y_raw":     np.ndarray,  # shape (44100,), dtype float64, max(abs)==1.0
    "frames":    np.ndarray,  # shape (98, 1103), dtype float64, C 连续
    "sr":        44100,       # int
    "frame_len": 1103,        # int
    "hop_len":   441,         # int
}
```

### 3.3 不变量（实现与测试都必须守）

| 编号 | 不变量 | 说明 |
|---|---|---|
| I1 | 非静音时 `np.max(np.abs(y_raw)) == 1.0` | 峰值元素除以自身，浮点意义下精确为 1 |
| I2 | 对所有 `k < n_frames`：`frames[k] == y_raw[k*hop_len : k*hop_len+frame_len]`；`L < frame_len` 时仅要求前 `L` 点相等 | 帧与原始信号严格对齐，不重不漏 |
| I3 | `frames.shape == (n_frames, frame_len)`，`frames.dtype == np.float64` | 下游按二维矩阵处理 |
| I4 | `L >= frame_len` 时 `n_frames == 1 + (L - frame_len) // hop_len` | 与 MATLAB `enframe` 一致 |
| I5 | `y_raw.size == L` 恒成立 | 短信号补零只发生在 `frames` 里，**不改变 `y_raw` 长度** |
| I6 | `set(result.keys()) == {"y_raw", "frames", "sr", "frame_len", "hop_len"}` | 接口冻结 |

### 3.4 帧索引 ↔ 采样索引（M2 必须按这个实现）

设 `L = len(y_raw)`，第 `k` 帧（0 基）：

- 起点采样：`s_k = k * hop_len`
- 终点采样（不含）：`e_k = min(k * hop_len + frame_len, L)`
- 帧中心时刻：`t_k = (k * hop_len + frame_len / 2) / sr`（秒）
- 由起止帧 `[k0, k1]` 切出一个音：`y_raw[k0 * hop_len : min(k1 * hop_len + frame_len, L)]`
- 被丢弃的尾部长度：`L - (frame_len + (n_frames - 1) * hop_len) < hop_len`

> 44.1 kHz / 25 ms / 10 ms：`L = 44100` 时 `n_frames = 98`，最后一帧覆盖 `42777..43880`，丢弃 220 个采样点（5 ms），**小于一个帧移**，不是 25 ms。

## 4. 算法流程（逐步）

### Step 0　参数校验

- `frame_ms <= 0` 或 `hop_ms <= 0` → `ValueError`
- `hop_ms > frame_ms` → `ValueError`
- 不在此处检查文件，交给 Step 1，让 `FileNotFoundError` 带原始路径抛出。

### Step 1　读取 wav

```python
sr, data = wavfile.read(audio_path)
```

- 用 `scipy.io.wavfile`，16-bit PCM 返回 `int16`，8-bit 返回 `uint8`，24-bit 返回 `int32`，浮点 wav 返回 `float32`；
- 不做重采样，`sr = int(sr)` 原样保留；
- 文件不存在、格式非法：不吞异常，由 GUI 层统一捕获并提示。

### Step 2　转 float64 + 单声道化

```python
y = data.astype(np.float64)   # 必须先转 float64
if y.ndim == 2:
    y = y.mean(axis=1)        # 双声道/多声道平均下混
elif y.ndim != 1:
    raise ValueError(...)
```

**为什么必须先 `astype(np.float64)` 再取绝对值**：`int16` 的最小值是 `-32768`，而 `np.abs(np.int16(-32768))` 在 16 位整数域会溢出，结果仍是 `-32768`（负数），导致 `max(abs(...))` 取错。先转 `float64` 可彻底避免。

补充处理：

| 情况 | 处理 |
|---|---|
| `data.dtype == np.uint8` | 8-bit PCM 是无符号的，先 `y = y - 128.0` 去掉中点偏置，否则直流分量会主导峰值 |
| `y.size == 0` | `ValueError("音频为空")` |
| 含 `NaN` / `Inf` | `ValueError`（正常 wav 不会出现，防 GUI 传入损坏文件） |
| `y.ndim > 2` | `ValueError` |

### Step 3　幅度归一化（严格“除以最大值”）

$$
y_{raw}[n] = \frac{y[n]}{\max_{0 \le m < L} \lvert y[m] \rvert}, \qquad n = 0, 1, \dots, L-1
$$

```python
peak = float(np.max(np.abs(y)))
if peak > 0.0:
    y_raw = y / peak
else:
    y_raw = y.copy()          # 全零信号：不做 0/0
    warnings.warn("音频全为零，跳过归一化", RuntimeWarning)
```

规则：

1. **整个文件只算一个 `peak`**，在全段所有采样点上取，不在帧内取，也不逐帧归一化；
2. 分母就是 `peak` 本身，不加 `eps`：`eps` 会让峰值变成 `1/(1+eps) ≈ 0.9999999999999998`，破坏 I1；
3. 只对 `peak == 0`（全静音/全零）走特判，返回全零，不抛异常——让 M2 去判断“没有音符”，而不是让预处理崩溃；
4. 归一化前后**不做**去直流、限幅、预加重、重采样；
5. 归一化在分帧**之前**完成，保证 `frames` 与 `y_raw` 同量级（否则 M2 用 `frames` 算能量、用 `y_raw` 切音，两者尺度不一致）。

### Step 4　帧长 / 帧移换算

$$
\text{frame\_len} = \max\left(1,\ \left\lfloor \frac{\text{frame\_ms}\cdot sr}{1000} + 0.5 \right\rfloor\right),\qquad
\text{hop\_len} = \max\left(1,\ \left\lfloor \frac{\text{hop\_ms}\cdot sr}{1000} + 0.5 \right\rfloor\right)
$$

**为什么用 `floor(x + 0.5)` 而不是 `int()` 或 Python `round()`**：

- 44.1 kHz × 25 ms = **1102.5**，正好落在半整数上；
- Python `round(1102.5)` 是银行家舍入，得 **1102**；MATLAB `round(1102.5)` 得 **1103**；
- 统一用 `floor(x + 0.5)`，与 MATLAB 对齐，得 **1103**，避免“为什么和论文/Matlab 差一个点”的答辩问题。

`max(1, ...)` 防止极小 `frame_ms` 在低采样率下取整成 0。

### Step 5　分帧

设 `L = len(y_raw)`：

**情况 A：`L >= frame_len`（正常情况）**

$$
n_{frames} = 1 + \left\lfloor \frac{L - \text{frame\_len}}{\text{hop\_len}} \right\rfloor
$$

```python
view = np.lib.stride_tricks.sliding_window_view(y_raw, frame_len)
frames = np.ascontiguousarray(view[::hop_len][:n_frames])
```

- `sliding_window_view` 是零拷贝视图，按 `hop_len` 跨步取帧后再 `ascontiguousarray` 拷成连续内存；
- `[:n_frames]` 做防御性截断，保证帧数严格符合 I4（正常情况下 `ceil((L-frame_len+1)/hop_len)` 已等于 `n_frames`）；
- 结果 `frames[k]` 严格等于 `y_raw[k*hop_len : k*hop_len+frame_len]`；
- 若组内 NumPy < 1.20（无 `sliding_window_view`），用 `numpy.lib.stride_tricks.as_strided` 等价实现，或退化为循环 + `np.stack`（音频不长，性能可接受）。

**情况 B：`L < frame_len`（超短音频）**

```python
padded = np.zeros(frame_len, dtype=np.float64)
padded[:L] = y_raw
frames = padded.reshape(1, frame_len)
```

- 只补 `frames`，`y_raw` **保持原长度**（I5）；
- 目的：避免下游拿到 `(0, frame_len)` 的空矩阵还要额外判空；
- M2 切音时用 `min(..., L)` 截断，补的零不会进入音符信号。

**情况 C：`L == 0`** 已在 Step 2 拦截，不会走到这里。

### Step 6　组装返回值

```python
return {
    "y_raw": y_raw,
    "frames": frames,
    "sr": int(sr),
    "frame_len": int(frame_len),
    "hop_len": int(hop_len),
}
```

不添加任何额外键；`frames` 已是可写连续数组，不需要再拷贝。

## 5. 伪代码（参考实现，非最终交付代码）

```python
import warnings
import numpy as np
from scipy.io import wavfile


def preprocess(audio_path: str, frame_ms: float = 25.0, hop_ms: float = 10.0) -> dict:
    # ---------- Step 0: 参数校验 ----------
    if frame_ms <= 0 or hop_ms <= 0:
        raise ValueError("frame_ms 和 hop_ms 必须为正数")
    if hop_ms > frame_ms:
        raise ValueError("hop_ms 不能大于 frame_ms（帧间会留空隙）")

    # ---------- Step 1: 读取 wav ----------
    sr, data = wavfile.read(audio_path)
    sr = int(sr)

    # ---------- Step 2: float64 + 单声道 ----------
    y = data.astype(np.float64)              # 必须先转 float64 再取 abs
    if y.ndim == 2:
        y = y.mean(axis=1)                   # 双声道/多声道平均下混
    elif y.ndim != 1:
        raise ValueError(f"不支持的音频维度: {y.ndim}")
    if data.dtype == np.uint8:               # 8-bit PCM 无符号，去中点偏置
        y = y - 128.0
    if y.size == 0:
        raise ValueError(f"音频为空: {audio_path}")
    if not np.all(np.isfinite(y)):
        raise ValueError("音频含 NaN/Inf")

    # ---------- Step 3: 幅度归一化（除以最大绝对值） ----------
    peak = float(np.max(np.abs(y)))
    if peak > 0.0:
        y_raw = y / peak
    else:
        y_raw = y.copy()
        warnings.warn("音频全为零，跳过归一化", RuntimeWarning)

    # ---------- Step 4: 帧长 / 帧移 ----------
    frame_len = max(1, int(np.floor(frame_ms * sr / 1000.0 + 0.5)))
    hop_len = max(1, int(np.floor(hop_ms * sr / 1000.0 + 0.5)))

    # ---------- Step 5: 分帧 ----------
    L = y_raw.size
    if L >= frame_len:
        n_frames = 1 + (L - frame_len) // hop_len
        view = np.lib.stride_tricks.sliding_window_view(y_raw, frame_len)
        frames = np.ascontiguousarray(view[::hop_len][:n_frames])
    else:
        padded = np.zeros(frame_len, dtype=np.float64)
        padded[:L] = y_raw
        frames = padded.reshape(1, frame_len)

    # ---------- Step 6: 组装上下文 ----------
    return {
        "y_raw": y_raw,
        "frames": frames,
        "sr": sr,
        "frame_len": frame_len,
        "hop_len": hop_len,
    }
```

**可选的调试入口**（不属于契约，方便组内单独验证）：

```python
if __name__ == "__main__":
    import sys
    ctx = preprocess(sys.argv[1])
    print({k: (v.shape if hasattr(v, "shape") else v) for k, v in ctx.items()})
```

## 6. 边界情况与错误处理

| 情况 | 行为 | 备注 |
|---|---|---|
| 文件不存在 | `FileNotFoundError`（不包装） | GUI 捕获后提示路径 |
| 文件不是 wav / 损坏 | `scipy` 抛出的异常原样上抛 | 不做静默兜底 |
| 空音频（0 采样） | `ValueError("音频为空")` | 无法归一化 |
| 全零 / 全静音 | `peak == 0`，返回全零 `y_raw`，`RuntimeWarning` | 由 M2 判“无音符” |
| 含 `NaN`/`Inf` | `ValueError` | 防损坏文件 |
| 双声道 | 平均下混 | 见 §10 反相风险 |
| 多声道（>2） | 平均下混 | 统一处理 |
| 8-bit PCM（`uint8`） | 减 128 去偏置 | 否则直流分量成峰值 |
| 24-bit / 32-bit / float wav | 转 `float64` 后按峰值归一化 | 位深不影响相对关系 |
| `frame_ms <= 0` / `hop_ms <= 0` | `ValueError` | 参数非法 |
| `hop_ms > frame_ms` | `ValueError` | 帧间空隙会破坏端点检测 |
| `L < frame_len` | `frames` 补零成 1 帧，`y_raw` 不变长 | I5 |
| `L` 不是 `hop_len` 整数倍 | 丢弃尾部，`< hop_len` | 与 `enframe` 一致 |

## 7. 复杂度与内存

- **时间**：读盘 `O(L)`，下混 `O(L)`，归一化 `O(L)`，分帧拷贝 `O(n_frames · frame_len) = O(L · frame_len / hop_len)`。44.1 kHz / 25 ms / 10 ms 时约为 `2.5 L`，整体 `O(L)` 常数约 4–5。
- **内存**：`frames` 约 `8 · L · frame_len / hop_len` 字节，`y_raw` 约 `8 L` 字节。
  - 1 s @ 44.1 kHz：`y_raw` 0.35 MB + `frames` 0.86 MB ≈ **1.2 MB**；
  - 10 s：≈ **12 MB**；
  - 60 s：≈ **74 MB**（`y_raw` 21 MB + `frames` 53 MB）。
- **结论**：桌面端单文件处理完全够用，本期不做分块/流式；若以后要处理超长音频，再考虑 `float32` 或分块，不在当前接口内。

## 10. 风险、权衡与答辩要点

| 问题 | 回答要点 |
|---|---|
| 为什么除以最大绝对值，而不是满量程 32768 或 RMS？ | 论文要求把信号“转化成一标准模式”；除以实际峰值后，不同录音设备/音量下同一音符的 `y_raw` 形状只差一个增益，峰值恒为 1，M2 的阈值有统一物理含义。除满量程会让安静录音整体偏小；RMS 会改变波形峰值关系，不符合“除最大值”的文档要求。 |
| 为什么先 `astype(float64)` 再取绝对值？ | `int16` 的 `-32768` 取绝对值会溢出仍为负，`max(abs(...))` 会算错。这是本模块最容易踩的坑。 |
| 为什么分帧不加 Hamming 窗？ | 短时能量/过零率要在真实帧能量上算；加窗会压制帧两端，音头音尾能量被低估，端点检测容易漏检。窗函数属于频域分析，留给 M3。 |
| 为什么丢弃尾部而不是补零覆盖？ | 与论文所用的 `enframe` 一致，帧数公式确定、可测试；丢弃长度 `< hop_len`（44.1 kHz/10 ms 时 < 10 ms），且 M2 切音时用 `min(..., L)` 可覆盖到文件末尾。补零覆盖会让末帧能量被人为拉低，反而制造一个假的下陷。 |
| 归一化为什么放在分帧前？ | 论文顺序就是“先归一化，再分帧”；同时保证 `frames` 和 `y_raw` 同尺度，M2 用 `frames` 判、用 `y_raw` 切时不会出现量级错位。 |
| 双声道平均会不会出问题？ | 反相立体声（左右声道相差 180°）平均后会相互抵消。当前按分工选择平均；若实测遇到反相录音，改成取左声道只需改一行，并在本文档记录变更。 |
| 短音频为什么只补 `frames` 不补 `y_raw`？ | `y_raw` 是切音数据源，补零会凭空多出静音采样，改变音符长度；`frames` 只是分析窗口，补零不影响切音。 |
| 归一化后峰值恒为 1，会不会丢绝对音量？ | 会，但本项目识别的是音高不是响度，论文明确要“标准模式”；若以后要做强弱音，需要额外保存 `peak`，那会破坏 5 键契约，属于新需求。 |
| `frame_len` 为什么是 1103 而不是 1102？ | 44.1 kHz × 25 ms = 1102.5；用 `floor(x+0.5)` 与 MATLAB `round` 对齐得 1103，避免与论文/Matlab 结果差一个采样点。 |
| 时域归一化和 M3 的 L2 归一化重复吗？ | 不重复。时域除峰值只是统一量级；M4 相关上界 $r_{ij} \le 1$ 靠的是**谱向量 L2 归一化**。两者作用域不同，缺一不可。 |
